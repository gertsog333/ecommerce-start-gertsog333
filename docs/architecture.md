# Architecture Overview

## Current State — Module 01 (Foundations & Setup)

At this stage of the course the system is a single containerized service, not yet the full microservices stack described in the course vision.

### Components

- **chat-agent** (Streamlit, Python 3.11-slim) — a single container exposing a chat UI on port 8501. It loads `data/products.csv` at startup and answers user queries with simple keyword matching against product name, category, and description columns.
- **Data layer** — flat files generated by `scripts/data/generate_ecommerce_data.py`: `products.csv/json`, `customers.csv`, `orders.csv`, `order_items.csv`, `support_conversations.csv`, `knowledge_base.csv/json`, and `product_embeddings.pkl` (384-dim, currently random vectors — a placeholder for real sentence-transformer embeddings used in later modules).
- **Deployment** — `docker-compose.yml` at repo root builds `docker/Dockerfile` and mounts the project directory plus `./data` into the container for live access to generated files.

### Request flow (current)

User -> Streamlit chat input -> pandas keyword filter over products.csv -> top-5 matches rendered in chat


No network calls, no external services, no persistence beyond the mounted CSVs — this is intentionally minimal so Module 01 can focus on environment setup and containerization basics.

## Target Architecture (later modules)

The repository is scaffolded for a full microservices system, built up module by module:

- **ML Service** (port 8001) — recommendation model serving (MLflow-tracked models).
- **RAG Service** (port 8002) — semantic search over `knowledge_base.json` / `products.json` using real embeddings and a vector store.
- **Agent Service** (port 8003) — LangChain-based orchestration combining ML + RAG + tool calls (per the AgentOps three-tier model: Foundation / Workflow / Autonomous, covered in Module 01 slides).
- **MLflow** (port 5000) — experiment tracking and model registry.
- **Grafana + Prometheus** (ports 3000 / 9090) — observability for latency, token usage, drift.
- **Ollama** — local LLM serving for the agent layer.

These services currently exist only as empty placeholders (`services/*/Dockerfile`, `docker/docker-compose.yml`) and will be implemented incrementally in Modules 2–14 per `COURSE_GUIDE.md`.

## Why this matters

Even a "basic" Module 01 deployment exercises the same operational concerns as the full system: containerization, environment configuration, data generation as a reproducible pipeline, and service health verification — the foundations the later MLOps/LLMOps/AgentOps layers build on.
